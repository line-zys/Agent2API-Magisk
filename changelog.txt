**本模块 26.11.24_7**　发布于 19:36 UTC+8

- DNS 那套补齐了两条会「命中率很低但一定复发」的坑：① dnsstub 原来只监听 UDP，而客户端（插件用的就是 glibc）收到 TC=1 后一定会改走 TCP 重问 127.0.0.1:53 —— 那里没人应答，于是长 TXT / 长 CNAME 链的域名解析直接失败，报错和原来的 dns error 一模一样，看着像没修好。现在补了 TCP 监听（TCP 不做 512 字节截断）。② 转发查询原来原样透传，客户端不带 EDNS0 时上游只肯回 512 字节；现在统一给上游注入 EDNS0(bufsize=1232)，再由我们按客户端能力决定「截断让它走 TCP」还是给完整应答。同时把串行阻塞改成每查询一线程（上限 32），上游丢包不再把整个 53 的应答拖到排队丢包；应答必须源地址正确 + 事务 ID 相同 + QR=1 才收（本机任意进程投毒进缓存的洞堵上）；超长报文用 MSG_TRUNC 识别后丢弃；缓存改成「原文 memcmp + 单调钟过期 + 命中递减 TTL」，rcode!=0 只缓存 1 秒。
- lib.sh 的 ag2a_dns_listen 以前只读 /proc/net/tcp{,6}，而 dnsstub 是 UDP（状态 07 不是 TCP 的 0A）⇒ 永远判「53 没在听」：dnsd 的「端口被占就让位」完全失效、会 1/2/5/10/30/60 秒无限重拉刷日志，check.sh 也一直误报「网关外连将全部 DNS 失败」。现在 TCP/UDP（含 IPv6）一起判，按 FILENAME 区分而不是数文件序号（没有 IPv6 时 /proc/net/tcp6 打不开，序号会错位）。
- updateJson 那条链原来是死的：https://line-zys.github.io/Agent2API-Magisk/update.json 返回 404 —— 仓库 Pages 从来没开过，管理器永远收不到版本信息，模块列表里的「更新」按钮也就永远不出现。已在仓库设置里开启 Pages（源 = main 根目录）并验证 update.json / changelog.txt 可访问；build_module.py 另外加了防呆：AG2A_SELF_REPO 不含 / 时直接报错（以前会打出 updateJson=https:///update.json 还照样通过占位符检查）。
- 自动更新不再「静默降级到无校验」：fetch() 以前丢掉下载器退出码、只看文件非空，被 --max-time 掐断的半截 JSON 也会被当成成功（解析出空 tag / 空 digest）；fetch_asset() 拿不到官方 digest 时以前会直接接受第一个源，而默认第一个源是第三方公共反代 —— 这两条叠起来就是一条能装进任意二进制的路。现在：下载器非 0 一律删文件报失败；digest 缺失直接拒绝安装（确要强装得显式开 AG2A_UPDATE_ALLOW_UNVERIFIED=1）。
- 自动更新的状态机修了三处「说了却做不到」：ui 替换失败时以前会照样写版本戳，于是下次判定「已是最新」再也不会修，只能重刷 zip（现在失败即回滚二进制、不写戳）；service.sh restart 的退出码以前被丢弃，端口被占也报「已重启」；tick 以前成功失败都记「今天查过了」，04:00 断网一次就停 24 小时，改钟点当天也不跑（现在失败只记一次尝试，1 小时后允许重试）。另外 date -d 不被支持时不再退化成 now+60（那会让 daemon 变回 60 秒一轮联网），改用纯算术兜底；TZ 指向不存在的 tzfile 时不再导出（否则 04:00 实际变成 12:00）。
- refresh.sh 写 module.prop 加锁：刷新点有六处会重叠，而临时文件名写死成 module.prop.tmp，两路同时截断就能把半截内容 mv 成真文件 —— 丢掉 id=/versionCode= 管理器会判模块无效。现在锁目录 + $$ 后缀 + 留 .bak，并且 grep 单独判失败（以前 { grep; printf; } > tmp 的组退出码取 printf，grep 失败也当成功，会把 module.prop 写成只剩一行 description）。
- uninstall.sh 不再依赖 pkill 存在，且清单补上 watchdog.sh 与 bin/dnsstub：以前 pkill 缺失时一个进程都杀不掉，删完目录还留着孤儿看门狗（每 60 秒去拉已删除的脚本）和 dnsstub（继续占着 127.0.0.1:53，让新装的 dnsd「让位退出」）。remove/disable 标记也改成「删不掉才写」。
- spawnhook 修了 argc==0 时的一个堆外写（calloc(argc+4) 之后还要写 NULL，正好越界 8 字节，网关是常驻多线程进程，会在之后某次 malloc/free 时 abort）；execve 劫持失败不再用原路径的 ENOENT 覆盖 loader 的真实错误（排障时那条 No such file or directory 会把人指向插件文件，真因被彻底掩盖）；execvp 自己按 PATH 搜索（以前直接转 execve，PATH 搜索整段丢失）；real 函数指针改在 constructor 里预先解析（多线程下惰性初始化存在数据竞争）。二进制由 CI 从 src/spawnhook/spawnhook.c 现编，不再用仓库里那份手工改过 .dynstr 的产物。
- 其它：customize.sh 的 ABI 判定改为 abilist / abi / uname -m 三路兜底（以前 getprop 不可用时直接 abort "需要 arm64 设备"，理由完全误导）；bin/dnsstub 补进 set_perm 列表；action.sh 的 read 每问前重置并在 EOF 时中止（以前半截 stdin 会把端口号当管理员用户名写进 admin_user）；control.sh 只转发认识的子命令（control.sh status 以前会一路掉进 service.sh 的前台 exec，把调用方永久阻塞）；build_module.py 的 zip 条目补 create_system=3 + S_IFREG、loader 进 EXEC；CI 的 gh release create 失败会退化为 upload --clobber，git push 被拒会 unshallow + rebase 重试。

**上游 3.5.1 的改动**

- 新增：Codex 订阅接入 `gpt-image-2` 图片生成与参考图编辑能力，图像冷却与文字对话额度独立计算、互不连坐。

- 更新：同步更新多语言文案、模型元数据同步脚本，并重建桌面端、手机端与多语言前端构建产物。
